# `/apply` workflow

Require a unique READY or PREPARED job and a reviewed package with an `apply-manifest.json`. Run the local preflight with the exact job ID and package.

Open the employer application using available browser tools. Verify employer, role, requisition and destination against preserved sources. Fill only routine fields supported by the authoritative profile. Verify autofilled values. Upload only the exact reviewed documents whose hashes match the manifest.

Stop for the user on salary, availability, work authorization, sponsorship, legal attestations, consent, demographics, signatures, unsupported facts, and any answer requiring judgment. Draft substantive responses from verified evidence and show them before entry when interpretation matters. Do not bypass login controls or CAPTCHA.

Inspect all sections, attachment names, answer limits, validation messages and unresolved fields. Save `apply-review.md` with completed fields, sources, uploaded hashes, blockers and current stage. State clearly: “Not submitted; awaiting your review.” Never press Submit.

Only after the user explicitly reports completed submission may `confirm-submitted` record APPLIED and the actual date. A prepared form, success-like banner, or earlier intent is not submission confirmation.
